# Mission Reflection

Out of the three platforms, AWS impressed me the most. It has the widest
range of services and the most regions around the world, which makes it
feel like the most complete option. I also liked that it has a huge
amount of documentation and community support, so it's easier to find
help when I get stuck.

While researching, I noticed that AWS, Azure, and GCP are actually more
similar than I expected. All three offer the same basic building blocks:
a service for renting virtual servers, a service for storing files, a
service for managing user identity, and support for networking and
databases. They just give these services different names and each one
focuses on a different strength.

I also learned that the "best" cloud platform really depends on what the
business needs. A startup with a small budget might do better with GCP's
flexible pricing, while a school or company that already uses Microsoft
tools would fit better with Azure. A business that needs to reach
customers worldwide might lean toward AWS because of its huge number of
regions. There's no single platform that's best for everyone — it
depends on the situation.

Acting as a Cloud Solutions Consultant taught me to think about a
client's needs first before picking a platform, instead of just picking
whichever one I'm most familiar with. I also ran into a real problem
while pushing my files to GitHub, where I typed a placeholder text
instead of my actual username, and I had to figure out how to fix the
remote link and push again. That showed me that troubleshooting is a
normal part of tech work, not something to be afraid of.

Finally, my GitHub Cloud Computing Portfolio has grown a lot after this
mission. It now shows that I can research and compare real cloud
platforms, write clear documentation, and organize a project properly
on GitHub, which are all skills I can use going forward in this course.
